# Maintenance

Use this checklist during substantive work or an explicitly requested maintenance run. No recurring task has been scheduled.

## Resume

1. Read PROJECT_INDEX.md and the selected STATUS.md.
2. Fetch the linked current design, decisions and relevant history from the current branch.
3. Check external active branches/PRs and asset metadata where relevant.
4. Compare accessible user context; log discrepancies before dependent changes.
5. Work from the stated baseline or isolated experiment, preserving its scope.

## Finish

1. Record new approvals and reversals with source and scope; do not label suggestions Approved.
2. Update authorized mechanics and preserve useful alternatives.
3. Refresh STATUS.md and append HISTORY.md; close or revise the relevant open question.
4. Update affected project/asset indexes and AI observations.
5. Verify changed links and source identity; commit a coherent update.

## Periodic check

- Compare every STATUS.md with its linked actual mechanics; inspect age, new commits and newer approvals. A recent administrative date does not prove mechanics were revalidated.
- Check for duplicate active masters, renamed files, incomplete exports, obsolete warnings and unrecorded reversals.
- Verify designated Drive file/folder IDs and read permissions through the connector. Do not infer public access from a valid owner link.
- Review conflict and observation registers without turning notes into tasks or canon automatically.
- Recover missing originals when available. Preserve unavailable status until readable evidence is obtained.
- Recheck external projects and rewrite this repository's pointer if their active branch changes.
- Keep the instructions master aligned with the actual workflow; manually copy it into ChatGPT when changed.
- Use the existing inventories and Git history; do not create repetitive recap documents for every session.
